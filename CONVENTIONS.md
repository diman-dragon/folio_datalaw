# Конвенция folio_datalaw

## 0. Порядок работы (обязателен для любого изменения)
1. **Конвенция** (этот файл): правила и что куда класть.
2. **Реестры** (`registry/`, карта и список в `registry/README.md`): что уже есть, кто чем владеет, что от чего зависит.
3. **Код**: только после первых двух шагов.

Не начинаем с поиска по коду. Сначала находим ответ в реестре, затем открываем ровно те файлы, которые он назвал.

| Вопрос | Реестр |
|---|---|
| Где это живёт, кому принадлежит файл, что от чего зависит? | `registry/components.json` |
| Какие виды компонентов и что им можно использовать? | `registry/kinds.json` |
| Какие есть события и кто их шлёт / слушает? | `registry/events.json` |
| Что и где хранится на диске? | `registry/storage.json` |
| Какие команды Rust и права есть у UI? | `registry/commands.json` |
| Какие горячие клавиши и жесты? | `registry/shortcuts.json` |
| Какие цвета / переменные CSS? | `registry/tokens.json` |
| Какие тексты интерфейса? | `www/js/core/strings.js` |
| Для чего нет теста и почему? | `scripts/checks/tests-exempt.json` |
| Какие нарушения известны и ещё не исправлены? | `registry/debt.md` |

Изменили то, что описывает реестр, — правим реестр **в том же шаге**. `pnpm check` сверяет реестры с кодом и называет, что дописать.

## 1. Компоненты: всё строится из компонентов
**Компонент** — именованная единица проекта с одним владельцем файлов. Его карточка в `registry/components.json`: ключ (kebab-case), `kind`, `about` (одна фраза), `files`, `ids`, `icons`, `uses`.

Вид (`kind`) задаёт, что компонент вправе использовать (`registry/kinds.json`):

| kind | что это | может использовать |
|---|---|---|
| service | шина, хранилище, строки, чистые функции, держатели состояния | service |
| format | движок формата (PDF, FB2) | service, format |
| native | Tauri-обёртки и Rust | service, native |
| domain | данные и правила без интерфейса | service, format, native, domain |
| ui | экран, панель, кнопка, жест | все, кроме tooling |
| flow | сценарий из нескольких компонентов (открыть, импортировать, убрать) | все, кроме tooling |
| tooling | скрипты проекта | tooling |

Правила (проверяет контракт, если не помечено «ревью»):
1. Каждый файл (js, css, rs, mjs) принадлежит **ровно одному** компоненту. Тест принадлежит владельцу своего файла (`x.test.js` → `x.js`, `x_tests.rs` → `x.rs`); сценарные тесты — `test-env`.
2. Нужен новый файл: найти компонент в реестре. Подходящего нет — сначала карточка нового компонента, потом файл.
3. Зависимости между компонентами: только по таблице видов, **без циклов**, и все перечислены в `uses` (список сверяется с реальными импортами в обе стороны).
4. Каждый `id` из `index.html` принадлежит одному компоненту (`ids`); каждая иконка перечислена в `icons`; публичные CSS-классы-примитивы живут в `ui-kit` (`classes`), новый примитив добавляется только туда.
5. Цвета — только токены из `theme.css` (`registry/tokens.json`), в обеих темах; своя переменная CSS, задаваемая из JS, — запись в `tokens.json` → `runtime`.
6. Общение между компонентами: импорт публичной функции, событие из `events.json` или держатель состояния (`active-doc`, `edit-state`). Новое событие — сначала в `events.json`.
7. Ревью: компонент не лезет в DOM и стили чужого компонента (чужой узел — через экспортируемую функцию или событие; общий корень `#viewer`, `#viewer-pages`, `#viewer-scroll` принадлежит `viewer-screen`).

Что делаю → что правлю первым:

| Добавляю | Сначала |
|---|---|
| файл в существующий компонент | `files` компонента (если нужен шаблон) и `uses`, если появился импорт чужого |
| новый компонент | карточка в `components.json` |
| id / иконку в разметку | `ids` / `icons` владельца |
| событие шины | `events.json` (`emit` и `on` — списки файлов) |
| ключ хранилища | `storage.json` (для данных документа — ещё `dropper`, и вызвать его в `app/remove-entry.js`) |
| команду Rust | `commands.json`, файл `commands/<имя>.rs`, `mod.rs`, `lib.rs`, JS-обёртка в `io/` |
| право Tauri | `commands.json` → `permissions` и `capabilities/default.json` |
| горячую клавишу | `shortcuts.json` |
| текст из JS | `core/strings.js` |
| цвет | `theme.css` (обе темы) и `tokens.json` |

## 2. Атомарность
- 1 файл = 1 ответственность. Первая строка каждого файла (`//` в JS и Rust, `/* */` в CSS) — одна фраза об этой ответственности.
- Лимиты размера: JS 110 строк, CSS 70, `.mjs` 70, Rust 120. Превысили — делим по ответственности.
- Один Tauri-command = один файл в `src-tauri/src/commands/`.
- Реэкспорты и «общие» файлы без логики не создаем.
- Ревью: если в первой строке нужен союз между разными делами («делает A и B»), это два файла. Файл, стили которого обслуживают два компонента, тоже делим.
- Автоматически «одну ответственность» не проверить (скрипт видит размер, заголовок и принадлежность компоненту), поэтому ревью обязательно. Известные отступления — в `registry/debt.md`; новые не добавляем, закрытые удаляем из списка.

## 3. Проверка при КАЖДОМ изменении
```
pnpm check
```
Это по порядку: контракт (`scripts/checks/*`) + ESLint → `node --test` → `cargo clippy -D warnings` → `cargo test`.
- Нет зеленого `pnpm check` — изменение не принято.
- Одно изменение = один файл = одна проверка. Пачки файлов без проверки между ними запрещены. Исключение — шаг, который по смыслу трогает несколько файлов сразу (перенос между компонентами, новая запись реестра вместе с файлом): тогда проверка после шага, а реестр правится в нём же.
- Новый файл логики идет с тестом `*.test.js` рядом (Rust — `*_tests.rs`). Контракт это проверяет (`scripts/checks/tests.mjs`). Исключение допускается только записью с причиной в `scripts/checks/tests-exempt.json` (DOM-экраны покрываются сценариями в `www/js/scenarios`). Чистая логика (геометрия, разбор, правила) под исключение не подпадает.
- Ошибку проверки чиним в том же шаге.

Что проверяет контракт:
- файлы: размер, заголовок-ответственность, наличие тестов, резолв импортов, изоляция Tauri (`__TAURI__` только в `io/bridge.js`), единая версия в `package.json` / `tauri.conf.json` / `Cargo.toml`;
- разметка: id из JS есть в `index.html`, иконки есть в `icons.svg`, доступность (`a11y`);
- реестры (`reg-*`): `components` (владелец каждого файла, форма карточек), `deps` (`uses` = реальные импорты, правила видов, циклы), `ids`, `icons`, `classes`, `events`, `storage`, `commands` (Rust ↔ lib.rs ↔ JS ↔ права), `shortcuts`, `strings`, `tokens`.

## 4. Версия
Каждое изменение поднимает последнюю цифру: `pnpm bump`, затем запись сверху `CHANGELOG.md`. `0.1.0` — только по команде владельца.

## 5. Безопасность
- Файловая система доступна только из Rust. Единственная точка чтения — команда `read_doc` через `doc_guard` (расширение `.pdf` / `.fb2` / `.fb2.zip`, сигнатура содержимого, лимит размера). Обход папок и проверка существования — `doc_scan`.
- Права в `capabilities/default.json` — минимум и совпадают с `registry/commands.json` → `permissions`. Расширяем только вместе с задачей, которой это нужно.
- PDF — недоверенный ввод: `isEvalSupported: false`, строгая CSP, скриптов PDF нет. Данные из хранилища тоже недоверенный ввод (пометки проходят `annot-valid`).

## 6. Форматы и переносимость
- Весь код вьювера и библиотеки — чистый JS без Tauri. Tauri знает только `www/js/io/bridge.js`.
- Новый формат — отдельная папка `www/js/formats/<fmt>/` и отдельный компонент вида `format`; выбор движка — `format-router`.
