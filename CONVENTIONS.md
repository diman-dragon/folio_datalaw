# Конвенция folio_datalaw

## 1. Атомарность
- Одна ответственность = один файл.
- Один файл содержит один компонент, одну функцию, один хук, один стор или один тип.
- Файл, который делает больше одного дела, разбивается на несколько.
- Реэкспорты только через index.ts, и он не содержит логики.

## 2. Обязательная проверка при КАЖДОЙ генерации
Любой сгенерированный или измененный файл проходит `pnpm check` до того, как считается готовым:
1. typecheck (tsc --noEmit)
2. lint (eslint)
3. format (prettier --check)
4. test (vitest)
5. check:rust (cargo clippy, предупреждения = ошибки)

Правила:
- Нет зеленого `pnpm check`, нет принятого файла.
- Одна генерация = один файл = одна проверка. Пачки файлов без проверки между ними запрещены.
- Каждый новый файл логики сопровождается тестом (*.test.ts рядом).
- Ошибка проверки исправляется в том же шаге, а не откладывается.

## 3. Безопасность
- Файловая система доступна только из Rust-команд.
- Минимальные permissions в capabilities, строгая CSP.
- PDF считается недоверенным вводом, скрипты в PDF.js отключены.
